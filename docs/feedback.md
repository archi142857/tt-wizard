# 버그 제보·기능 제안 (GitHub 이슈)

10/31 사용자: "그 버그 제보나 기능 제안 이런 거 받는 창구 필요함", 창구는 "GitHub 이슈", "앱에서 입력해서 제보하면 깃허브에 쌓이도록 할 수 있으면 좋을듯".
백엔드 update73 이 양식을 두었고, 앱 화면(정보 탭의 '의견 보내기')은 디자인이 자리·문구를 정한 뒤 프론트엔드가 넣는다.

## 1. 지금: 앱에서 쓰고 GitHub 계정으로 올린다

- 양식: `.github/ISSUE_TEMPLATE/bug.yml`(버그 제보, 라벨 `bug`), `idea.yml`(기능 제안, 라벨 `enhancement`). GitHub 이슈 양식(issue forms)이라
  레포의 'New issue' 화면에도 같은 둘이 보인다. 맨 위에 '올린 글은 누구나 볼 수 있어요. … 개인정보는 적지 마세요.'(버그 양식은 정정·삭제 요청은 메일로).
- 앱은 쓴 글을 채운 '새 이슈' 주소를 바깥 링크로 연다(스토어 앱은 Capacitor Browser: 안드로이드 Custom Tab·iOS 인앱 Safari, 웹은 새 탭).
  쓴 사람이 자기 GitHub 계정으로 [Submit new issue] 를 누르면 레포 이슈에 쌓인다. 앱은 아무것도 보내지 않는다(서버 없음).
- 주소(칸 id 가 양식과 같아야 채워진다. GitHub '주소 쿼리로 이슈 만들기'는 양식의 글 칸을 id 로 채운다):

  ```
  https://github.com/Archi142857/tt-wizard/issues/new?template=bug.yml&title=<[버그] 제목>&what=<내용>&app=<앱 정보>
  https://github.com/Archi142857/tt-wizard/issues/new?template=idea.yml&title=<[제안] 제목>&what=<내용>&app=<앱 정보>
  ```

  | 칸 | 버그 | 제안 | 앱이 넣는 것 |
  | --- | --- | --- | --- |
  | `title` | `[버그] …` | `[제안] …` | 머리말을 붙인 제목(주소로 주면 양식의 `title` 을 덮는다). 제목 칸이 없으면 내용 첫 줄 |
  | `what` | 있었던 일(필수) | 제안(필수) | 쓴 내용 |
  | `steps` / `why` | 다시 생기는 순서 | 쓰고 싶은 때 | 앱에 칸을 두면(선택) |
  | `app` | 앱 정보 | 앱 정보 | `0.9.0 · Android 14 · 앱 · 2026년 2학기`: 판(`APP_VERSION`), 운영체제와 주 판(user agent에서), 앱·웹·설치한 웹 앱, 보던 학기. 시간표·기기 이름은 넣지 않는다 |

  값은 `encodeURIComponent`. `labels` 는 넣지 않는다(쓰기 권한이 없는 사람이 주면 GitHub 가 404. 라벨은 양식이 단다).
- 길이: 주소가 길면 GitHub 가 `414 URI Too Long` 을 낸다. 한글 한 글자가 주소에서 9자(`%EC%9D%B4`)라 제목 50자·내용 500자 안팎에서 끊는다
  (주소 전체 6,000자 아래. 넘으면 보내기 전에 줄여 달라고 한다).
- 알아 둘 것: GitHub 계정이 있어야 올릴 수 있다(로그인 화면이 먼저 뜰 수 있다). 주소를 열면 올리기 전이라도 쓴 글이 주소째 GitHub 에 간다(GitHub 접속 기록).
  안드로이드에 GitHub 앱이 깔려 있으면 그 앱이 주소를 받을 수 있고, 그 앱이 양식 채우기를 따르지 않으면 빈 양식이 뜬다(폰에서 볼 것).
- 개인정보: 앱이 모으는 것이 없어 스토어 데이터 보안('수집 없음')은 그대로다. 처리방침에는 '의견 보내기는 GitHub 이슈로 공개되고 쓴 사람의 계정으로 올라간다'를 법무가 본다.

## 2. 나중(정하지 않음): 계정 없이 앱에서 바로

앱이 작은 중계 서버(예: Cloudflare Worker 무료판)에 글을 보내고, 서버가 봇 토큰으로 이슈를 만든다(공개 레포 대신 비공개 레포에 쌓을 수 있다).
계정 없는 학생도 보낼 수 있지만 앱이 데이터를 보내게 되어 스토어 데이터 보안·개인정보 라벨과 처리방침을 고치고, 스팸 막기(주소마다 횟수, 길이)와
토큰 관리(사용자가 만든 fine-grained 토큰을 서버 비밀 값으로만. 레포·앱에 넣지 않는다)가 필요하다. 법무가 본 뒤 사용자가 정한다(`요청_법무.md` 10/31).
앱 화면은 1과 같고 '보내기'가 하는 일만 바뀐다.
